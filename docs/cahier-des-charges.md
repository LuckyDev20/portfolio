# Cahier des charges — Portfolio de Loukman Ouedraogo

> Version 1.0 — Novembre 2026
> Auteur : Loukman Ouedraogo, développeur web et mobile

---

## 1. Contexte

Je termine mon BTS en développement web et mobile et je souhaite entrer sur le marché du travail.
Ce portfolio est ma vitrine professionnelle : il présente mon profil, mes compétences et mes réalisations.
C'est aussi mon **premier projet complet**, mené de la conception au déploiement.

## 2. Objectifs

Après sa visite, un visiteur doit pouvoir :

1. **Comprendre qui je suis** et ce que je sais faire, en moins de 30 secondes.
2. **Voir mes réalisations** (démos en ligne et code source).
3. **Me contacter facilement** (formulaire, email, WhatsApp).
4. **Consulter mon GitHub** et **télécharger mon CV**.

## 3. Public cible

| Cible | Ce qu'elle cherche |
|---|---|
| Recruteurs au Burkina Faso | Un profil sérieux, des compétences claires, un moyen de contact rapide |
| Recruteurs et entreprises à l'étranger | Un site en anglais, des projets concrets, un code propre sur GitHub |
| Clients freelance | Ce que je peux réaliser pour eux, et un contact direct (WhatsApp) |

## 4. Contenu du site

### 4.1 Accueil / Présentation
- Nom, titre (« Développeur web et mobile ») et une phrase d'accroche.
- Courte présentation : parcours, motivation, ce que je recherche (emploi, stage, missions freelance).
- Boutons d'action : « Voir mes projets », « Me contacter », « Télécharger mon CV ».

### 4.2 Compétences
- Technologies regroupées par catégorie : Front-end, Back-end, Mobile, Bases de données, Outils.
- Présentation honnête du niveau (pas de pourcentages inventés).

### 4.3 Projets
Pour chaque projet :
- Capture d'écran ou aperçu
- Titre et description courte (le problème résolu)
- Technologies utilisées
- Lien vers la démo en ligne
- Lien vers le code sur GitHub

> **Contrainte importante :** ajouter un nouveau projet doit être simple
> (modifier un seul fichier de données, sans toucher à la mise en page).

### 4.4 Contact
- Formulaire de contact fonctionnel (nom, email, message), avec validation des champs et message de confirmation.
- Adresse email visible.
- Bouton WhatsApp.
- Liens vers GitHub (et LinkedIn une fois le profil créé).

## 5. Fonctionnalités — priorisation (méthode MoSCoW)

| Priorité | Fonctionnalité |
|---|---|
| **Must** (indispensable) | Les 4 sections · Responsive mobile · Formulaire de contact fonctionnel · Liens GitHub et WhatsApp · Mise en ligne |
| **Should** (important) | Version anglaise avec bouton de changement de langue · CV téléchargeable · SEO de base |
| **Could** (bonus) | Mode sombre · Animations légères · Section parcours / formation |
| **Won't** (pas dans cette version) | Blog · Espace d'administration · Comptes utilisateurs |

## 6. Exigences non fonctionnelles

- **Responsive** : affichage correct sur téléphone, tablette et ordinateur.
- **Performance** : site léger et rapide, y compris avec une connexion lente (images optimisées).
- **Accessibilité** : contrastes suffisants, textes alternatifs sur les images, navigation au clavier.
- **SEO** : titre et description de page, balises sémantiques, aperçu correct quand le lien est partagé.
- **Qualité du code** : code lisible et organisé, historique Git propre, README clair.
- **Compatibilité** : navigateurs récents (Chrome, Firefox, Safari, Edge).

## 7. Identité visuelle

- **Ton** : sérieux, moderne, créatif — tout en restant professionnel.
- **Couleur principale** : bleu (piste principale, à valider sur la maquette).
- **Style** : design sobre et aéré, typographie lisible, une touche créative sans surcharge.

## 8. Contraintes

- Hébergement gratuit ou à très faible coût.
- Textes en anglais : je dois comprendre chaque phrase publiée.
- Projet réalisé seul, avec accompagnement.

## 9. Livrables

1. Ce cahier des charges
2. Maquettes (mobile et ordinateur)
3. Code source sur GitHub, avec README
4. Site en ligne avec une adresse publique

## 10. Critères de validation

Le projet est terminé quand :
- [ ] Les fonctionnalités **Must** fonctionnent en ligne.
- [ ] Le site s'affiche correctement sur téléphone et ordinateur.
- [ ] Un message envoyé par le formulaire arrive bien dans ma boîte mail.
- [ ] Le README explique le projet, les technologies et comment le lancer.
- [ ] Je peux expliquer chaque choix technique et chaque partie du code.
